# parking mirea

Информационная система учёта заявок на парковку. Владельцы регистрируют автомобили и подают заявки на парковочные места, а система следит за занятостью мест, датами и допустимыми переходами статусов.

## О приложении

Заявка здесь отдельная сущность с жизненным циклом: «Новая», «Подтверждена», «Завершена» или «Отменена». Система не даёт занять одно место двум заявкам на пересекающееся время, поставить один автомобиль в две активные заявки, подать заявку на чужой автомобиль и изменить завершённую или отменённую заявку. Телефоны и госномера приводятся к единому виду, поэтому `89991234567` и `+7 (999) 123-45-67` считаются одним номером, а латинские буквы в госномере заменяются кириллическими двойниками.

Система растёт поэтапно, и у неё несколько клиентов.

Консольное приложение работает с владельцами, автомобилями, парковочными местами и заявками. В каждом разделе есть поиск, фильтры по нескольким столбцам одновременно, сортировка и статистика за период. Данные выгружаются в Excel. Десктоп-клиент на JavaFX работает поверх той же бизнес-логики и показывает заявки, их карточки и статистику.

Серверная часть на Spring Boot отдаёт REST API со входом по JWT и обновляемыми сессиями. Через неё работают заявки и владельцы с заметками, категории клиентов, массовые операции, аналитика, управление пользователями с ролями и журнал аудита. API описано в Swagger. Web-клиент для сотрудников написан на Next.js, в нём уже есть заявки, владельцы, пользователи и журнал аудита.

Приложение находится в разработке. Остальные разделы web-клиента и мобильное приложение для Android ещё впереди.

## Архитектура

Консольный и JavaFX-клиенты обращаются к сервисному слою с бизнес-правилами, а тот к репозиториям, которые работают с PostgreSQL напрямую через JDBC. Web-клиент работает с базой через REST API, у которого свой набор слоёв: контроллеры, сервисы, репозитории Spring Data и миграции Flyway.

```
консоль, JavaFX ── сервисы ── репозитории (JDBC) ──┐
                                                    ├── PostgreSQL
Next.js ── прокси /api ── REST API (Spring) ──────┘
```

Статусы заявок и типы мест вынесены в справочники базы данных. Запросы к `/api` из web-клиента проксируются на backend, поэтому cookie входа остаются на адресе приложения.

## Как запустить

Потребуются Git, JDK 21, Maven и Docker с Docker Compose. Для web-клиента ещё Node.js 24 и pnpm.

```bash
git clone https://github.com/vleypi/parking-mirea.git
cd parking-mirea
docker compose -f docker/docker-compose.yml up -d
```

PostgreSQL запустится на `localhost:5432` с готовой схемой и тестовыми данными из `sql/init.sql`. Чтобы вернуть исходные данные, нужно удалить том командой `docker compose -f docker/docker-compose.yml down -v` и запустить базу заново.

Консольное приложение и десктоп-клиент:

```bash
cd javafx-client
mvn compile exec:java
mvn javafx:run
```

Backend. Первый администратор создаётся из переменных `BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_PASSWORD`, пока в базе нет пользователей. Перед запуском в продакшене нужно задать `JWT_SECRET_BASE64`.

```bash
cd backend
BOOTSTRAP_ADMIN_LOGIN=admin BOOTSTRAP_ADMIN_PASSWORD=<пароль> mvn spring-boot:run
```

Миграции Flyway применяются при старте. API доступно по адресу http://localhost:8080, документация по адресу http://localhost:8080/swagger-ui.html.

Web-клиент:

```bash
cd frontend
pnpm install
pnpm dev
```

Приложение откроется по адресу http://localhost:3000. Адрес backend задаётся переменной `API_URL`. Проверка перед коммитом запускается командой `pnpm check`.

## Запуск КР3 в Docker и Swagger

Для КР3 backend и его база запускаются одной командой в Docker. Нужен только Docker Desktop: JDK и Maven ставить не обязательно, приложение собирается внутри контейнера. Эта база отдельная от базы КР2 из `docker/` и слушает порт 55432, поэтому они не мешают друг другу.

Из корня проекта в PowerShell:

```powershell
.\backend\start-compose.ps1
```

При первом запуске скрипт создаст в корне файл `.env` со случайными паролем базы, JWT-секретом и паролем администратора и напечатает этот пароль. Затем он соберёт образ, поднимет PostgreSQL и backend, дождётся готовности и выведет адреса. Файл `.env` не коммитится и никому не пересылается.

То же самое без скрипта, если `.env` уже есть:

```powershell
docker compose --env-file .env -f backend/docker-compose.yml up -d --build --wait
```

| Что | Адрес |
|---|---|
| Web-клиент (после `pnpm dev`) | http://localhost:3000 |
| Swagger UI | http://localhost:8080/swagger-ui.html |
| Вход для Swagger | http://localhost:8080/swagger-login.html |
| REST API | http://localhost:8080/api |
| OpenAPI JSON | http://localhost:8080/v3/api-docs (группы: `/v3/api-docs/vehicles`, `/spots` и т.д.) |
| Health | http://localhost:8080/actuator/health |
| PostgreSQL | `localhost:55432`, база, пользователь и пароль из `.env` |

**Администратор.** Логин и пароль берутся из `BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_PASSWORD` в `.env`. Учётная запись создаётся при первом старте, пока в базе нет пользователей. Остальных сотрудников администратор заводит в разделе «Пользователи».

**Swagger.** Swagger доступен только Администратору. Сначала нужно войти на `/swagger-login.html`: access-токен ляжет в HttpOnly-cookie, и Swagger будет отправлять его со всеми запросами сам, ничего вставлять в Authorize не нужно. Эндпоинты разбиты на группы по сущностям (переключатель вверху справа), у каждого есть краткое описание.

**Web-клиент в dev-режиме** работает с backend из Docker:

```powershell
cd frontend
pnpm install
pnpm dev
```

Если pnpm не установлен, подойдёт `npx pnpm install` и `npx pnpm dev`. Запросы `/api` проксируются на адрес из переменной `API_URL` (по умолчанию http://localhost:8080).

**Тесты backend** идут на встроенной H2 и Docker не требуют:

```powershell
cd backend
mvn test
```

**Остановка и сброс базы.** Остановить контейнеры, сохранив данные:

```powershell
.\backend\stop-compose.ps1
```

Удалить базу вместе с данными; при следующем запуске Flyway создаст её заново, а администратор появится снова из `.env`:

```powershell
.\backend\stop-compose.ps1 -Reset
```

Окончательное удаление записей по умолчанию выключено; чтобы его включить, нужно поставить `PERMANENT_DELETE_ENABLED=true` в `.env` и перезапустить backend.

## Структура

```
parking-mirea/
├── javafx-client/       консоль и десктоп-клиент на JavaFX
│   └── src/main/java/ru/mirea/project/
│       ├── model/       сущности, справочники, диапазоны
│       ├── service/     бизнес-правила, поиск, фильтры, статистика
│       ├── repository/  доступ к данным через JDBC
│       ├── ui/          консольные меню
│       └── fx/          окна JavaFX
├── backend/             REST API на Spring Boot
│   └── src/main/
│       ├── java/ru/mirea/parking/   controller, service, repository, domain, security
│       └── resources/db/migration/  миграции Flyway
├── frontend/            web-клиент на Next.js
├── android-client/      место под мобильное приложение
├── sql/init.sql         схема базы и тестовые данные
├── docker/              PostgreSQL в Docker Compose
└── docs/                требования к работам, ER-диаграмма, правила коммитов
```
