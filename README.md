**Информационная система учёта заявок на парковку: консольное приложение с постепенным развитием в десктоп-клиент, REST API и мобильное приложение.**

> **Проект находится в активной разработке.** Реализована первая контрольная работа (КР1), консольное Java-приложение. Следующие этапы (КР2, КР3, КР4) пока не начаты.

Парковочная система: сквозной учебный проект, который поэтапно вырастает из консольного приложения в полноценную систему с несколькими клиентами. Владельцы регистрируют свои автомобили и создают заявки на конкретные парковочные места, а система следит за соблюдением бизнес-правил: занятостью мест, корректностью дат и допустимыми переходами статусов заявки.

*Семестровый проект, РТУ МИРЭА.*

## Проблема

Учёт заявок на парковочные места вручную приводит к двойным бронированиям одного места на пересекающееся время и потере истории обращений владельцев. Система формализует заявку как отдельную сущность с жизненным циклом статусов и проверяет бизнес-правила при создании, изменении и смене статуса.

## Функционал

### Реализовано (КР1)

- Четыре связанные сущности: владелец, автомобиль, парковочное место, заявка на парковку. Полный CRUD для каждой через JDBC. Используется только `PreparedStatement`, try-with-resources, без конкатенации SQL.
- Бизнес-правила заявки:
  - владелец, автомобиль и место с указанными ID должны существовать;
  - автомобиль должен принадлежать владельцу заявки;
  - дата и время окончания строго позже даты и времени начала;
  - запрет двух заявок на одно место с пересекающимися интервалами (учитываются только активные статусы «Новая» и «Подтверждена»);
  - один автомобиль не может быть в двух активных заявках на пересекающееся время;
  - допустимые переходы статуса заявки («Новая» → «Подтверждена»/«Отменена», «Подтверждена» → «Завершена»/«Отменена»); «Завершена» и «Отменена» являются конечными статусами;
  - изменять можно только активные заявки («Новая» и «Подтверждена»).
- Правила владельца: имя и телефон обязательны, телефон уникален, владельца с автомобилями или заявками удалить нельзя.
- Правила автомобиля: гос. номер обязателен и уникален, марка и модель обязательны, автомобиль с заявками удалить нельзя.
- Правила места: номер места положительный и уникален, тип из справочника `SpotType`, тариф неотрицательный, место с заявками удалить нельзя.
- Приведение ввода к единому формату:
  - телефон в любом виде (`89991234567`, `+7 (999) 123-45-67`, `9991234567`) хранится как `+7-999-123-45-67`;
  - гос. номер хранится заглавными кириллическими буквами без пробелов, латинские буквы-двойники заменяются (`a123bc77` → `А123ВС77`);
  - имя с заглавной буквы в каждом слове (`иван иванов` → `Иван Иванов`), марка и модель с заглавной первой буквы.
- Каждая сущность имеет своё меню с одинаковым каркасом: показать все, найти по ID, создать, изменить, удалить, поиск, фильтры и сортировка, статистика. У заявок дополнительно смена статуса.

| Сущность | Поиск | Фильтры | Сортировка | Статистика за период |
|---|---|---|---|---|
| Владельцы | по имени; по телефону | с автомобилями / без; с активными заявками | по имени; по дате регистрации | автомобили, заявки по статусам, сумма оплат |
| Автомобили | по гос. номеру; по марке или модели; стояли на парковке в период | по владельцу; по марке | по гос. номеру; по марке | заявки по статусам, часы на парковке, сумма оплат |
| Парковочные места | по номеру; свободные на период | по типу; по диапазону тарифа | по номеру; по тарифу | заявки, занятые часы, выручка |
| Заявки | по гос. номеру; по имени владельца; по номеру места | по статусу; за период; по типу места | по началу; по дате создания | заявки по статусам, выручка, средняя длительность |

- Период вводится двумя датами, Enter оставляет границу открытой (пустой период означает «за всё время»). Заявка относится к периоду, если пересекается с ним. Свободными считаются места без активных заявок на период, часы считаются по неотменённым заявкам, деньги по завершённым.
- Общая статистика за период (9 показателей): владельцы, автомобили, места, заявки, активные, завершённые, отменённые, занятые места прямо сейчас, выручка по завершённым заявкам.
- Списки выводятся таблицами с заголовками, вместо голых ID показываются имена владельцев, гос. номера и номера мест.
- Экспорт данных в `.xlsx` через Apache POI: листы «Владельцы», «Автомобили», «Парковочные места» и «Заявки».
- Статусы заявок и типы мест хранятся в таблицах-справочниках `request_statuses` и `spot_types`, основные таблицы ссылаются на них внешними ключами. У каждого значения enum есть код (`NEW`), id (связь с БД) и русское название («Новая»), пользователь везде видит русские названия и выбирает значение номером из списка.
- Вывод всех шести таблиц базы данных из меню.
- Устойчивость к некорректному вводу: текст вместо числа, несуществующий ID, битая дата, неизвестный статус или тип места, ошибки БД. При ошибке в поле программа переспрашивает только это поле.
- Схема БД, тестовые данные и ER-диаграмма.

## Архитектура

Консольный клиент обращается к сервисному слою с бизнес-правилами, а тот обращается к репозиториям, работающим с PostgreSQL напрямую через JDBC. Меню каждой сущности наследуется от абстрактного `EntityMenu`, который задаёт общий каркас пунктов и обрабатывает ошибки в одном месте; `MainMenu` работает со списком `EntityMenu`, не зная конкретных классов.

```text
MainMenu ─ UserMenu / VehicleMenu / SpotMenu / RequestMenu (extends EntityMenu, ввод через ConsoleInput)
       |
UserService / VehicleService / SpotService / RequestService / StatisticsService (валидация и бизнес-правила)
       |
UserRepository / VehicleRepository / SpotRepository / RequestRepository (JDBC, PreparedStatement)
       |
PostgreSQL
```

## Модель данных

Четыре связанные сущности и два справочника:

- **User**: владелец автомобиля.
- **Vehicle**: автомобиль, принадлежит владельцу (`vehicles.user_id → users.id`).
- **Spot**: парковочное место с типом и тарифом за час, ссылается на справочник типов (`spots.spot_type_id → spot_types.id`).
- **Request**: заявка на парковку, ссылается на владельца, автомобиль, место и справочник статусов (`user_id`, `vehicle_id`, `spot_id`, `status_id → request_statuses.id`).
- **Справочники `request_statuses` и `spot_types`**: id, английский код и русское название. В Java им соответствуют enum `RequestStatus` и `SpotType` с теми же id; оба реализуют общий интерфейс `LookupValue`.

## Установка и запуск

Для запуска нужны JDK 21+, Maven, Docker и Docker Compose.

Поднимите PostgreSQL в контейнере:

```bash
docker compose -f docker/docker-compose.yml up -d
```

База будет доступна на `localhost:5432` (база `project_db`, пользователь `project_user`) со схемой и тестовыми данными из `sql/init.sql`. Параметры подключения лежат в `backend/src/main/resources/db.properties`.

Соберите и запустите консольное приложение:

```bash
cd backend
mvn compile exec:java
```

Остановить контейнер с базой:

```bash
docker compose -f docker/docker-compose.yml down
```

### Пересоздать базу с нуля

Скрипт `sql/init.sql` выполняется только при первом создании тома с данными, поэтому для возврата к исходным тестовым данным том нужно удалить:

```bash
docker compose -f docker/docker-compose.yml down -v
docker compose -f docker/docker-compose.yml up -d
```

### Если что-то не работает

- Ошибка подключения к базе: убедитесь, что контейнер запущен (`docker ps`) и порт 5432 не занят другим PostgreSQL. Если занят, остановите локальный сервер или измените порт в `docker/docker-compose.yml` и в `db.properties`.
- `mvn` не находит Java 21: проверьте `java -version` и переменную `JAVA_HOME`.

## Пример использования

После запуска откроется главное меню:

```text
1. Владельцы
2. Автомобили
3. Парковочные места
4. Заявки на парковку
5. Общая статистика за период
6. Экспорт в Excel
7. Таблицы базы данных
0. Выход
```

Пункты 1–4 открывают меню сущности с одинаковым набором действий:

```text
1. Показать все      2. Найти по ID      3. Создать      4. Изменить      5. Удалить
6. Поиск             7. Фильтры и сортировка             8. Статистика
0. Назад
```

- **Владельцы**: имя и уникальный телефон; поиск по имени или цифрам телефона; статистика по владельцу за период.
- **Автомобили**: гос. номер, марка, модель; поиск машин, стоявших на парковке в заданный период.
- **Парковочные места**: номер, тип из списка («Стандартное», «Для людей с инвалидностью», «Для электромобилей»), тариф; поиск свободных мест на период.
- **Заявки на парковку**: при создании программа покажет автомобили владельца и список мест. При нарушении бизнес-правил (чужой автомобиль, занятое место, автомобиль уже на парковке, некорректные даты) выводится понятное сообщение. Пункт `9. Сменить статус`: новый статус выбирается номером из списка, недопустимый переход (например, из «Завершена») отклоняется.
- При изменении Enter оставляет текущее значение поля, `q` в любом поле отменяет действие.
- **Экспорт в Excel**: файл `parking_export.xlsx` с четырьмя листами сохраняется в папке, из которой запущено приложение.
- **Таблицы базы данных**: справочники `request_statuses`, `spot_types` и таблицы `users`, `vehicles`, `spots`, `requests`.
